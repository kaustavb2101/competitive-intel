## (3) The buildings question — honest path
Real extruded footprints for all 77 provinces already **exist as measured Overture data** in two reachable places: the 77 per-province R2 catchments (verified: samut-sakhon 39.5 MB, chon-buri 43.2 MB, khon-kaen 41.4 MB, phuket — all HTTP 200/206 with real polygon rings `{p,h,fa,cx,cy,ty}`) **and** the Overture S3 bucket direct (HTTP 200 from cloud). The honest fix is **not another pull** — it is packaging what we have into **one national `buildings.pmtiles`**, which serves only the tiles in view via HTTP range requests (hundreds of KB) instead of a 40 MB whole-province JSON. That is exactly what Step 2's already-written CI job does; the lone hard dependency is `tippecanoe`, which is a CI-image binary (pinned 2.62.0 in the workflow), **not a geo-block and not a desktop task**. Honest caveats: the R2 catchments are capped at 180k buildings/province, so dense metros are truncated vs a fresh S3 pull (the S3 route in `data-tiles.yml` avoids this — prefer it); and even if the tile build slips, Steps 1+4 mean no scene is ever empty — POI columns, population, rings, and lite footprints render from committed measured data regardless.
